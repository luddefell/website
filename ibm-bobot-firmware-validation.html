ibm bobot firmware validation system

Power Systems validation, agent tools, and developer notifications

Bobot began as an IBM watsonx challenge: give an AI assistant a way to observe and interact with physical Power systems. Working with the firmware validation team turned that idea into a broader lab problem. Four technicians were manually checking system states across roughly 30 servers, then recording test outcomes for engineering review. I worked on the physical test system and the software that made its results useful to the wider Power engineering team.

from physical tests to engineering results

The Python-controlled hardware-in-the-loop platform combined robotic actuation, cameras, sensors, and Power system telemetry. It coordinated physical actions with firmware test steps, including fault injection over SSH and Telnet, so the team could observe hardware responses and investigate failures with repeatable evidence.

  • Integrated camera-based status detection with robotic controls for Power system operator-panel tests, using watchdogs, timeouts, interlocks, and safe sequencing.
  • Built a Model Context Protocol (MCP) interface for watsonx Bob agent tool calling: check system status, list tests, run a test, and retrieve results.
  • Channeled test results and evidence into IBM Engineering Test Management (ETM) on Jazz, with development updates and HIL/SIL outcomes also visible through web dashboards and notifications.

To keep developers informed, I deployed a DevOps notification system built from three Java/Quarkus microservices. REST APIs, message queues, and PostgreSQL moved engineering events from internal sources through the application to Slack and email. Together with Jazz ETM and the dashboards, this gave teams visibility into Power product development and test outcomes.

  1. Notification SourceCollects engineering events and test updates.
  2. ApplicationProcesses and routes events through the queue.
  3. Notification DeliverySends updates to Slack and email.
